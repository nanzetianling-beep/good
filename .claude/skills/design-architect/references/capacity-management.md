# 容量管理手順 (Capacity Management)

`/design-system/` がコンテキストウィンドウを圧迫することを防ぐための運用手順。

## 監視の目安

以下のいずれかに該当したら、作業の冒頭でユーザーに最適化を**提案**する(勝手に実行しない):

- トークンファイル1つが 200行 を超えた
- `design-system/` 直下の合計が 15ファイル を超えた
- changelog.md が 100エントリ を超えた
- 同一カテゴリに使途不明・重複疑いのトークンが 3つ以上ある

## 最適化の選択肢(提案順)

1. **アーカイブ**: 90日以上参照されていないスタイル・廃止テーマを `archive/YYYY-MM/` へ移動。archive 内の README に「いつ・なぜ・何を」移動したか記録する。
2. **トークン統合**: 近似値のトークン(例: `radius-6` と `radius-8`)を統合。統合時は置換対象の一覧を提示してから実行する。
3. **外部ドキュメント化**: 使用頻度の低い詳細ルール(例: 印刷用スタイル、レガシーブラウザ対応)を `guidelines/appendix/` に分離し、README からリンクのみ残す。
4. **changelog のローテーション**: 古いエントリを `archive/changelog-YYYY.md` へ移動し、直近分のみ残す。

## 原則

- アーカイブは削除ではない。履歴と意図は必ず追跡可能に保つ。
- 最適化そのものも changelog に記録する(何を・なぜ圧縮したか)。
