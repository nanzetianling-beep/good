# トーン&マナー・表記統一ガイド

トーン設定（リライト手順2）と表記統一（手順3）のリファレンス。Reference Folder があればそちらを優先し、これは既定値・判断基準として使う。

---

## トンマナで決めるべき項目

新しい案件・媒体では、書き始める前に次を決めて固定する。決めた内容は文書の最後までブレさせない。

| 項目 | 選択肢の例 |
| --- | --- |
| 文体 | 敬体（です・ます）／常体（だ・である） |
| フォーマル度 | かたい・ビジネス／標準／フレンドリー・カジュアル |
| 一人称 | 私／僕／わたし／弊社／当社／（省略） |
| 二人称（読者の呼び方） | あなた／みなさん／お客さま／（省略） |
| 語尾のクセ | 言い切り多め／やわらかめ／体言止めの可否 |
| 一文の長さ | 短め（〜40字）／標準／長めも可 |
| 漢字とかなの比率 | 漢字多め（かたい）／ひらがな多め（やわらかい） |
| カタカナ・専門用語 | 積極的に使う／かみくだく／初出で説明 |
| 記号・絵文字 | 使う／使わない／！？の可否 |
| 感情表現 | 抑える／適度／熱量高め |

決められない項目があれば、Reference Folder のサンプルから実例を拾って合わせる。サンプルもなければ用途別の既定（SKILL.md「用途別のトーン指針」）に従う。

## トンマナ設定シート：記入例3種

上の表を実際に埋めた見本。新しい案件では、これを叩き台にコピーして書き換えると速い。数値（文字数・回数）はあくまで初期値で、Reference Folder があればそちらの実測値で上書きする。

### 記入例A：カジュアルSNS運用（D2CブランドのX公式アカウント）

| 項目 | 設定 |
| --- | --- |
| 文体 | 軽い敬体（です・ます）。体言止め・言い切りを混ぜてよい |
| フォーマル度 | フレンドリー。友だちより少し丁寧、店員より近い距離 |
| 一人称／二人称 | 一人称は原則なし（必要なら「中の人」）。読者は「みなさん」か省略 |
| 語彙 | 話し言葉寄り。「ちょっと」「じつは」「こっそり」OK。ネットスラング（「神」「〜すぎるw」）は使わない。商品名は正式名称で統一 |
| 文末 | 「です・ます」6割、体言止め・言い切り・問いかけで4割。「！」は1投稿1回まで |
| 一文の長さ目安 | 〜35字。1投稿は120字前後、3〜4行で改行して余白を作る |
| 絵文字・記号ポリシー | 絵文字は1投稿2個まで（顔・手・矢印系のみ）。「👇」は誘導のときだけ。装飾線・機種依存記号・「✨」の連打はNG。ハッシュタグは2個まで |
| NG表現 | 「〜させていただきます」「弊社」「ご愛顧」「拡散希望」「必見」、値引きの連呼、他社比較 |

| 項目 | 設定 |
| --- | --- |
| 文体 | 敬体。キメの一文のみ常体可（1記事2回まで） |
| フォーマル度 | 標準〜ややかたい。読者は業務時間中に読む前提 |

| 項目 | 設定 |
| --- | --- |
| 文体 | 敬体。手紙のように1人に語りかける |

## トーンオブボイスの4要素（ブランドボイス設計）

ブランドや個人の「声」をそろえたいときは、次の4要素で言葉遣いを分解して定義すると再現しやすい。

- **語彙（Vocabulary）**：使う言葉・避ける言葉。専門用語をそのまま使うか、かみくだくか。
- **文体（Style）**：敬体/常体、一文の長さ、文の組み立て、リズム。
- **態度（Attitude）**：読者との関係。対等な仲間か、頼れる専門家か、案内役か。
- **感情（Emotion）**：熱量・ユーモア・落ち着き。どんな気分を読者に残したいか。

設計の流れは「パーソナリティ定義 → ターゲット理解 → 4要素の設定 → Do/Don'tリスト作成 → ガイドライン化」。特に **Do（使ってよい表現）とDon't（避ける表現）を具体例で並べる**と、複数人・複数回で書いてもブレにくい。Reference Folder の文体を抽出するときも、この4要素とDo/Don'tの枠で整理すると精度が上がる。

## 敬体と常体

- **敬体（です・ます）**：やわらかく丁寧。解説記事、企業・商品紹介、ブログ、メルマガ、マニュアルなど読者に語りかける文書向き。
- **常体（だ・である）**：簡潔で断定的、説得力が出る。ニュース、レポート、論文、勢いを出したいSNSなど。
- **原則、混在させない**。敬いのある文体とそうでない文体が混ざると、リズムが崩れ違和感が生まれる。
- **例外**：地の文が敬体でも、箇条書きの各項目やカギ括弧の会話文を常体にするのは許容される。また読み物では、地の文は敬体でキメの一文だけ常体、のように意図的に混ぜてリズムを作る手法もある（乱用しない）。
- 混在が事故として起きやすいのはAI出力の典型症状。最終チェックで必ず統一を確認する。

## 表記ゆれの統一

同じ意味の語は文書内で1つに固定する。JTF日本語標準スタイルガイドでは、送り仮名は内閣告示「送り仮名の付け方」の本則・例外に従うのが原則。**語ごとの具体的な統一リスト（50語超）は `references/hyokiyure-list.md` を参照**。ここでは判断の枠だけ示す：

- **送り仮名**：「申し込み／申込み／申込」→ どれか1つに。「行う／おこなう」「表す／表わす」。
- **漢字を開く/閉じる**（漢字にするか、ひらがなにするか）：
  - 開く（ひらがな推奨）の代表例：「事→こと」「時→とき」「様々→さまざま」「出来る→できる」「頂く→いただく」「下さい→ください」「為→ため」「等→など」「所→ところ（副詞的用法）」。
  - 補助動詞・形式名詞はひらがなにするのが読みやすい（「見ていく」「言っておく」「食べてみる」）。
- **カタカナ長音**：「サーバー／サーバ」「ユーザー／ユーザ」→ 媒体で統一（一般向けは長音ありが主流）。
- **数字**：半角/全角、算用数字/漢数字の使い分けを統一（「一つ」「1つ」、「1000」「1,000」）。
- **英数字と和文の間**：スペースを入れるか入れないかを統一。
- **記号**：三点リーダー「…」、ダッシュ「——」、波ダッシュ、感嘆符・疑問符の後ろの空き、括弧の種類（「」『』（）［］）を統一。
- **句読点**：読点「、」の打ち方（1文に多すぎない）。理系文書では「，．」を使う流儀もある。媒体に合わせる。

迷ったときの優先順位：**Reference Folder の実例 ＞ 媒体の慣習 ＞ 一般的な読みやすさ（開く方向）＞ 一文書内で一貫**。

## 用途別のトーン詳細

### SNS投稿（X / Instagram など）
- 距離が近い。常体または軽い敬体。一文を短く。
- 冒頭の1行で引きを作る（結論・意外性・問い）。
- 体言止め・問いかけ・改行の余白で勢いとリズム。
- 1投稿1メッセージ。詰め込まない。
- ハッシュタグは内容に沿ったものを少数。絵文字は媒体とブランド次第。
- かしこまりすぎ・広告臭は逆効果。

### ブログ記事
- 敬体が基本。読み物として地の文で説明する。
- 導入で読者の課題・場面に触れてから本題へ（前置きの一般論は短く）。
- 見出しで構造を見せる。ただし1〜2文ごとの細切れ見出しは避ける。
- 箇条書きは並列項目に限定。流れは文章で。
- 体験・具体例・数字で一次情報感を出す。
- テンプレ締め（「いかがでしたか」）は使わず、次の一歩や書き手の視点で。

### メールマガジン
- 1対1で語りかける手紙のトーン。敬体。
- 一人称・二人称の距離を最初から最後まで一定に。
- 流れ：件名 → 書き出し（続きを読ませる）→ 本題 → 行動喚起（CTA）。
- 1通1テーマ。あれもこれもと詰めない。
- 売り込みを主語にせず、読者の利益を主語にする（「新機能をリリースしました」より「あなたの〇〇が楽になります」）。
- プレーンテキスト配信では、Markdown記号（`**` や `#`）や一部絵文字がそのまま表示される。装飾に頼らず改行・空行で読みやすくする。

## トーンを保つ運用のコツ

- 決めたトンマナは短いチェックリスト（Do/Don't）にして、書き終わりに照合する。
- 長文では途中でトーンが漂流しやすい。中盤・終盤を特に確認する。
- 複数人・複数回で書く場合ほど、Reference Folder とチェックリストの共有が効く。
- 最後は必ず音読する。目で追うと見逃す不自然さも、耳で聞くと気づける。
