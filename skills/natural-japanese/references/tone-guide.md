# トーン&マナー・表記統一ガイド

トーン設定（手順2）と表記統一（手順3）のリファレンス。Reference Folder があればそちらを優先し、これは既定値・判断基準として使う。

---

## トンマナで決めるべき項目

新しい案件・媒体では、書き始める前に次を決めて固定する。決めた内容は文書の最後までブレさせない。

| 項目 | 選択肢の例 |
| --- | --- |
| 文体 | 敬体（です・ます）／常体（だ・である） |
| フォーマル度 | かたい・ビジネス／標準／フレンドリー・カジュアル |
| 一人称 | 私／僕／わたし／弊社／当社／（省略） |
| 二人称（読者の呼び方） | あなた／みなさん／お客さま／（省略） |
| 語尾のクセ | 言い切り多め／やわらかめ／体言止めの可否 |
| 一文の長さ | 短め（〜40字）／標準／長めも可 |
| 漢字とかなの比率 | 漢字多め（かたい）／ひらがな多め（やわらかい） |
| カタカナ・専門用語 | 積極的に使う／かみくだく／初出で説明 |
| 記号・絵文字 | 使う／使わない／！？の可否 |
| 感情表現 | 抑える／適度／熱量高め |

決められない項目があれば、Reference Folder のサンプルから実例を拾って合わせる。サンプルもなければ用途別の既定（SKILL.md「用途別のトーン指針」）に従う。

---

## 敬体と常体

- **敬体（です・ます）**：やわらかく丁寧。Webサイト、ブログ、メルマガ、マニュアルなど読者に語りかける文書向き。
- **常体（だ・である）**：簡潔で強い。レポート、スライド、社説的な断定、勢いを出したいSNSなど。
- **原則、混在させない**。ただし読み物では、地の文は敬体でキメの一文だけ常体、のように意図的に混ぜてリズムを作る手法もある（乱用しない）。
- 混在が事故として起きやすいのはAI出力の典型症状。最終チェックで必ず統一を確認する。

## 表記ゆれの統一

同じ意味の語は文書内で1つに固定する。代表的な判断ポイント：

- **送り仮名**：「申し込み／申込み／申込」→ どれか1つに。「行う／おこなう」「表す／表わす」。
- **漢字を開く/閉じる**（漢字にするか、ひらがなにするか）：
  - 開く（ひらがな推奨）の代表例：「事→こと」「時→とき」「様々→さまざま」「出来る→できる」「頂く→いただく」「下さい→ください」「為→ため」「等→など」「所→ところ（副詞的用法）」。
  - 補助動詞・形式名詞はひらがなにするのが読みやすい（「見ていく」「言っておく」「食べてみる」）。
- **カタカナ長音**：「サーバー／サーバ」「ユーザー／ユーザ」→ 媒体で統一（一般向けは長音ありが主流）。
- **数字**：半角/全角、算用数字/漢数字の使い分けを統一（「一つ」「1つ」、「1000」「1,000」）。
- **英数字と和文の間**：スペースを入れるか入れないかを統一。
- **記号**：三点リーダー「…」、ダッシュ「——」、波ダッシュ、感嘆符・疑問符の後ろの空き、括弧の種類（「」『』（）［］）を統一。
- **句読点**：読点「、」の打ち方（1文に多すぎない）。理系文書では「，．」を使う流儀もある。媒体に合わせる。

迷ったときの優先順位：**Reference Folder の実例 ＞ 媒体の慣習 ＞ 一般的な読みやすさ（開く方向）＞ 一文書内で一貫**。

## 用途別のトーン詳細

### SNS投稿（X / Instagram など）
- 距離が近い。常体または軽い敬体。一文を短く。
- 冒頭の1行で引きを作る（結論・意外性・問い）。
- 体言止め・問いかけ・改行の余白で勢いとリズム。
- 1投稿1メッセージ。詰め込まない。
- ハッシュタグは内容に沿ったものを少数。絵文字は媒体とブランド次第。
- かしこまりすぎ・広告臭は逆効果。

### ブログ記事
- 敬体が基本。読み物として地の文で説明する。
- 導入で読者の課題・場面に触れてから本題へ。
- 見出しで構造を見せる。ただし1〜2文ごとの細切れ見出しは避ける。
- 箇条書きは並列項目に限定。流れは文章で。
- 体験・具体例・数字で一次情報感を出す。
- テンプレ締め（「いかがでしたか」）は使わず、次の一歩や書き手の視点で。

### メールマガジン
- 1対1で語りかける手紙のトーン。敬体。
- 一人称・二人称の距離を最初から最後まで一定に。
- 流れ：件名 → 書き出し（続きを読ませる）→ 本題 → 行動喚起（CTA）。
- 1通1テーマ。あれもこれもと詰めない。
- 売り込みを主語にせず、読者の利益を主語にする（「新機能をリリースしました」より「あなたの〇〇が楽になります」）。

## トーンを保つ運用のコツ

- 決めたトンマナは短いチェックリストにして、書き終わりに照合する。
- 長文では途中でトーンが漂流しやすい。中盤・終盤を特に確認する。
- 複数人・複数回で書く場合ほど、Reference Folder とチェックリストの共有が効く。
